# Extension architecture

`core/new-api` remains the upstream source. All SaaS functionality belongs in `extensions/` and uses four narrow core seams:

1. merge public navigation items into `use-top-nav-links.ts`;
2. merge admin navigation items into the authenticated sidebar registry;
3. mount the generated extension routes in the TanStack router build;
4. load the backend platform router during server bootstrap.

The seam changes are deliberately kept as patch files in `patches/`. They are the only intended source-level divergence from upstream. Extension source is copied into ignored `core/new-api/platform/` and `core/new-api/web/src/platform/` by `scripts/assemble-extensions.sh`.

## Content management flow

Public pages call public platform APIs, which return published content only. Admin pages call admin platform APIs and require the existing new-api administrator session. Content, products, orders, payments and VIP data must use the platform database/schema, never new-api core tables.

## Upgrade procedure

1. Update `core/new-api` from its upstream remote.
2. Run `./scripts/sync-upstream.sh`.
3. Resolve a patch only if upstream changed one of the four seams.
4. Run the build and integration checks appropriate to the changed code.

Do not edit `routeTree.gen.ts`; it is generated by TanStack Router.
